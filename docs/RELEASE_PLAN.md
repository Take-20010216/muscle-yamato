# MUSCLE YAMATO ストア配信 リリース計画

最終更新: 2026-06-07

App Store / Google Play への配信を目標とした、費用・手順・チェックリストのまとめ。
迫られずに、上から順に進めればOK。各ステップは独立して止めても問題ない設計。

---

## 0. 現状

- **形態**: Next.js 16 製の PWA（Webアプリ）
- **ホスティング**: Vercel（Hobbyプラン）
- **DB/認証**: Supabase（無料枠）
- **公開URL**: https://muscle-yamato.vercel.app
- **コールドスタート対策**: UptimeRobot で `/api/keepalive` を5分おきにping（設定済み）
- **主要機能**: 記録 / ルーティン / 統計 / 自己ベスト / カレンダー履歴 / コミュニティ（共有・コメント・絵文字リアクション）

---

## 1. 技術方針：Capacitor でラップ

今の Web 資産を**作り直さず**ネイティブアプリの殻に包む。

- Web（Next.js）コードはそのまま流用
- iOS / Android のネイティブプロジェクトを生成
- ネイティブ機能（プッシュ通知など）をプラグインで追加できる

### ⚠️ 最重要：Apple 審査ガイドライン 4.2 対策
「ただのWebサイトをアプリ化しただけ」は **リジェクトされやすい**。
通すには Web にない**ネイティブ機能を最低1つ**載せるのが実質必須。

→ 本アプリでは **プッシュ通知**を採用予定（コミュニティ機能と好相性）。
  例：「仲間があなたの投稿にリアクションしたよ」「今日のトレーニング、まだ？」

Google Play は緩く、PWA をほぼそのまま（TWA方式）配信可能。

## 3. ロードマップ（この順で進める）

- [ ] **STEP 1: アプリ素体の確定**
  - コミュニティ機能のバグ取り・UI確定
  - 一通りの動作確認（記録→共有→リアクション→コメント）
- [ ] **STEP 2: Capacitor 導入**
  - Capacitor をプロジェクトに追加
  - iOS / Android プロジェクト生成
  - Mac のシミュレータでアプリとして起動できる状態を作る
  - ※ ここまで無料。「本当にアプリになる感触」を確認してから課金判断できる
- [ ] **STEP 3: プッシュ通知の実装**（Apple審査対策＋機能強化）
  - 通知許可フロー
  - Supabase 側のトリガー（リアクション/コメント時に通知）
  - iOS は APNs、Android は FCM の設定
- [ ] **STEP 4: ストア素材の準備**
  - アプリアイコン（各サイズ）
  - スプラッシュスクリーン
  - ストア用スクリーンショット（端末サイズ別）
  - アプリ説明文・キーワード
- [ ] **STEP 5: 法務・規約の整備**
  - プライバシーポリシー（必須）
  - 利用規約
  - サポート窓口（メール等）
  - データ削除導線（アカウント削除）
- [ ] **STEP 6: 開発者登録**
  - Apple Developer Program 登録（年会費）
  - Google Play Console 登録（初回費用）
- [ ] **STEP 7: ビルド提出 → 審査 → 公開**
  - iOS: Xcode から App Store Connect へアップロード
  - Android: Play Console へ AAB アップロード
  - 審査対応（リジェクト時は修正して再提出）

## 5. 審査でつまずきやすいポイント（事前対策）

1. **Guideline 4.2（最低限の機能）**
   → プッシュ通知などネイティブ機能を載せる（STEP 3で対応）
2. **プライバシー対応**
   → プライバシーポリシー必須。収集データの明示（メール・トレ記録等）
3. **アカウント削除導線**
   → App内からアカウント＆データ削除できる導線が必須（Apple要件）
4. **サインイン**
   → 第三者ログイン（Apple/Google）を使う場合「Sign in with Apple」併設が必要なケースあり。現状メール認証なら問題になりにくい
5. **未成年・健康データの扱い**
   → 医療アドバイスではない旨を明記すると安全
